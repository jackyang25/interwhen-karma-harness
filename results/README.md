# Results

This directory holds working copies of export bundles produced by
`notebooks/03_analysis.py`. **Bundle contents are gitignored** — only this
README and `RESULTS.md` are committed.

**Findings writeup:** see [`RESULTS.md`](./RESULTS.md) — the analysis of the
currently-present bundle, written against the artifacts on disk.

## What's in a bundle

`03_analysis.py` writes a single bundle directory containing:

| Path | Contents |
|---|---|
| `MANIFEST.json` | sha256 + size for every file in the bundle |
| `provenance/provenance.json` | Models, dataset, hardware, commit SHAs, run records |
| `provenance/pip_freeze.txt` | Pinned dependency list at export time |
| `provenance/mcp_calculator_schemas.json` | Snapshot of EkaCare's calculator schemas at export time (drives the extractor vocabulary) |
| `prompts/` | Locked condition prompts (verbatim from top-level `prompts/`) + the runtime-generated `extractor_prompt.txt` (regenerated by the preflight from the MCP schemas — this is the actual prompt Sonnet saw) |
| `raw/condition_*.csv` | Per-vignette rows per condition |
| `analysis/*.csv` `analysis/*.json` | Accuracy table, McNemar comparisons, cost/latency, per-category, verifier characterization, etc. |
| `plots/*.png` | Pareto frontier, per-category heatmap |
| `study_gates/apparatus_gate.json` | Apparatus reproduction result |
| `study_gates/apparatus_results.csv` | Per-row apparatus data |
| `vllm_server.log` | vLLM stdout/stderr from the run |

## Where the bundle lives

`03_analysis.py` writes to `/tmp/karma_export/` on the Databricks cluster.
Each run wipes and rewrites this path (bundles are derived from the
per-condition parquets in `/dbfs/results/qwen3_condition_*_full/`, which
are protected by the backup-on-rerun discipline). Download bundles to this
local directory when you want to inspect them.

## Provenance

Each bundle's `MANIFEST.json` records the sha256 of every artifact. The
`provenance.json` inside it records:
- Model IDs and revisions
- Dataset revision (`ekacare/medical_calculator_eval` test split)
- Git SHAs for the harness and interwhen
- Hardware, DBR version, cluster name
- Export timestamp
- Per-condition run records (from `02_run_all`'s orchestrator log)

Treat DBFS condition parquets as the system of record; the local bundle is
a derived working copy.
